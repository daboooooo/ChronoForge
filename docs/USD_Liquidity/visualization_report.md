## 概览

本知识库现有的 15 张图表（`assets/js/diagrams.js`）均为**概念示意图、流程图或表格**，尚未接入任何真实历史数据。本报告识别出 **12 大可视化主题**，涵盖历史回测、实时监控、预测推演三个层次，每个主题都有明确的数据源（FRED 序列 ID）、数据粒度和预期视觉效果。

所有变量的 FRED 序列 ID 已在 [variables.json](data/variables.json) 中逐一标注，可直接调用。

## 九、实现建议

### 数据源接入优先级
所有 FRED 序列均可通过 FRED Observations API 直接获取。推荐按以下顺序接入：

1. **第一批（日频/周频，立即可用）**：WRESBAL、WTREGEN、RRPONTSYD、WALCL、EFFR、SOFR、DGS10、DFII10、VIXCLS
2. **第二批（市场数据，需交易所 API）**：DXY（ICE）、TLT（ETF）、BTC（交易所）、罗素2000/标普（指数商）
3. **第三批（加密特有）**：稳定币供给（链上数据）、BTC ETF 净流入（ETF.com）

### 与现有代码的集成方式
- 现有 [diagrams.js](assets/js/diagrams.js) 中的函数返回纯静态 SVG，可以保留作为**概念层**
- 新增数据图表模块（如 `assets/js/charts.js`），使用轻量级库（Chart.js / ECharts / Plotly.js 均可离线部署）
- 在 [data/variables.json](data/variables.json) 中已标注 FRED 序列 ID，可直接构建 API 调用层

### 证据等级可视化原则
- 会计恒等式（FORMULA 系列）→ 实线，蓝色，无争议
- 机制关系（REL 系列，verification_status = author_claimed）→ 实线，灰色
- 经验观察（CASE 系列）→ 虚线，橙色，标注"待验证"
- 假设（hypothesis）→ 点线，红色，标注"⚠️ 假设"
- 数据缺失或不完整 → 灰色占位 + 提示"数据待补充"
